## What this lane is for

These candidates are fitted after they are written. Each one is scored untrained (step 0) and after 500 and 1000 steps of imitation fitting on expert demonstrations; the checkpoint is chosen on separate probe episodes, and step 0 stays selectable, so a mutation that fitting cannot improve is recorded as "fitting rejected". A mutation is useful here only if it makes the structure easier to fit while keeping what already works.

Each slot below is fixed in advance: its parent is a hand-written reference that fitting is known to improve, and its mutation scope is predeclared. You may not choose a different parent or scope.

## What to return

Propose exactly {n} bounded mutations, one per slot above, in the same order. Do not write code here; each mutation is implemented separately with its parent's source in front of the implementer.

Rules for every mutation (one that breaks a rule fails its slot, and nothing is filled in for you):
- Exactly one structural change to the parent, stated in one sentence in "structural_change". Not a rewrite: keep at least {min_kept_percent}% of the parent's parameters with the same name, initial value and range.
- "parameter_changes" names every parameter that differs from the parent: "adds" (new names), "removes" (parent names deleted) and "changes" (parent names kept with a different initial value or range). At most {max_changes} names in total. Stay inside the slot's scope.

- Preserve the parent's behaviour: name in "protected_behaviors" what the parent already does that the mutation must not lose.
- Predict which fitting diagnostic improves: "predicted_metric" must be exactly one of: {fitting_metrics}. "predicted_direction" is "increase" or "decrease".
